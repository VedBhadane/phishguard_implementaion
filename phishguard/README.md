# PhishGuard

A working implementation of the system motivated by the survey
**"Multi-Paradigm, Explainable, and Self-Healing Streaming Framework for
Real-Time Phishing Detection"**. It covers all four future-research
directions from the survey's Section 6 with runnable code:

| Survey direction | What's implemented | Where |
|---|---|---|
| Direction 1 — Drift-Adaptive Streaming Pipelines (Gap 1) | A DDM (Drift Detection Method) statistical monitor that watches live prediction accuracy and auto-triggers retraining on a buffered recent window when the error distribution shifts | `src/drift.py`, `src/streaming_simulation.py` |
| Direction 2 — API-Independent Hybrid Feature Architecture (Gap 3, Gap 5) | 40 features combining URL lexical analysis + HTML structural analysis — no WHOIS, no Google Safe Browsing, no Alexa rank, no network calls at all | `src/features.py` |
| Direction 3 — Explainability (Gap 2) | Per-prediction local explanations via single-feature ablation (see "About the explainability method" below — this is a lightweight, honestly-labeled substitute for the survey's proposed LLM-assisted explainer, not an LLM call) | `src/model.py` (`explain()`) |
| Direction 4 — Lightweight Real-Time Deployment (Gap 6) | A RandomForest classifier (sub-millisecond inference, no GPU) wrapped in a Flask web app + REST API | `src/app.py`, `run_app.py` |

**Important — read this first:** there is no internet access in the
environment this was built in, so the model is trained on a
**synthetic dataset** generated by rules that mimic real phishing/legit
patterns (see `data/generate_dataset.py`). It's good enough to prove
the whole pipeline works end to end, but **do not use it as-is to
protect real users** — swap in a real dataset first. Instructions for
that are below.

## 1. What you need to download / install

- **Python 3.10+** (built and tested on 3.12)
- The Python packages in `requirements.txt`:
  ```
  pandas>=2.0
  numpy>=1.24
  scikit-learn>=1.3
  beautifulsoup4>=4.12
  Flask>=3.0
  joblib>=1.3
  ```
  Nothing else — no XGBoost, no SHAP, no TensorFlow. That's deliberate:
  it keeps the whole thing installable offline and keeps inference fast
  enough for real-time use (Direction 4).

Nothing needs to be manually downloaded from anywhere else — the
dataset is generated locally by a script in this project.

## 3. Exact commands to run it, in order

Open a terminal **in the `phishguard/` folder** (i.e. `cd` into it —
every command below assumes you're standing in this folder) and run
these commands one at a time.

### Step 1 — create a virtual environment (recommended, not required)
```bash
python3 -m venv venv
source venv/bin/activate        # on Windows: venv\Scripts\activate
```

### Step 2 — install dependencies
```bash
pip install -r requirements.txt
```

### Step 3 — generate the synthetic training dataset
```bash
python3 data/generate_dataset.py --n 2500 --seed 42
```
This writes `data/phishing_dataset.csv` (5,000 rows: 2,500 legitimate +
2,500 phishing examples with a `url`, `html`, `label` column each).
You can regenerate with a bigger `--n` for a larger dataset.

### Step 4 — train the model
```bash
python3 train.py --data data/phishing_dataset.csv
```
This prints holdout accuracy/precision/recall/F1 and the top global
feature importances, and saves the trained model to
`models/phishguard_model.joblib`.

### Step 5 — run the web app
```bash
python3 run_app.py
```
Then open **http://localhost:5000** in a browser. Paste a URL (and
optionally the page's HTML source — right-click → "View Page Source"
→ copy/paste) and click Scan. You'll get a verdict, a probability, and
a table of the features that most influenced the decision.

### Step 6 (optional) — try the REST API directly
```bash
curl -X POST http://localhost:5000/api/scan \
  -H "Content-Type: application/json" \
  -d '{"url": "http://192.168.1.5/paypal/verify.php", "html": "<html>...</html>"}'
```
`html` is optional — you'll get a (less accurate) verdict from the URL
alone if you omit it.

`GET http://localhost:5000/api/health` returns the current model's
holdout metrics, useful for a monitoring dashboard or uptime check.

### Step 7 (optional) — see the drift-detection / self-healing demo
This simulates a stream of incoming URLs, optionally with phishing
tactics that "evolve" partway through, and shows the system detecting
the shift and automatically retraining:
```bash
# stable stream, no injected drift -- should show 0 false retrain triggers
python3 -m src.streaming_simulation --steps 400 --no-drift

# with a simulated tactic shift at step 200 -- watch it detect + retrain
python3 -m src.streaming_simulation --steps 400 --drift-at 200
```
Note: running this **overwrites** `models/phishguard_model.joblib`
with whatever it retrains on mid-simulation. Re-run Step 4 afterward
if you want to restore the full-dataset-trained model before using the
web app again.

## 4. Using a real dataset instead of the synthetic one

The synthetic generator exists only because this was built without
internet access. Before using PhishGuard for anything real:

1. Get a real labeled dataset, e.g.:
   - UCI Machine Learning Repository — "Phishing Websites Data Set"
   - Kaggle — search "phishing URL dataset" (several maintained ones)
   - PhishTank's URL feed (phishing side) + a Tranco/majestic top-sites
     list (legitimate side)
2. Produce a CSV with these columns:
   - `url` (required)
   - `html` (optional — raw page HTML; leave blank/omit if you only have URLs)
   - `label` (required — `1` for phishing, `0` for legitimate)
3. Run:
   ```bash
   python3 train.py --data path/to/your_real_dataset.csv
   ```
   That's it — `features.py`, `model.py`, `drift.py`, and `app.py` are
   all dataset-agnostic; nothing else needs to change.

## 5. About the explainability method (read before trusting the numbers)

The survey's Direction 3 calls for an LLM-assisted explainer paired
with a fast classifier. This build has no LLM API access, and the
`shap` package isn't installable offline either, so `model.py`
implements a small, honestly-documented substitute instead of faking
either one:

For a given prediction, each feature's "contribution" is the change in
predicted phishing-probability when that one feature is reset to the
training set's median value, holding everything else fixed:

```
contribution(feature) = P(phish | actual x) − P(phish | x with that feature at its median)
```

This is a single-feature marginal/ablation estimate — a simplified,
non-combinatorial cousin of the Shapley-value idea behind SHAP. It's
cheap (one extra forward pass per feature) and gives an honest,
per-prediction "why" — but it is **not** exact SHAP (it doesn't average
over feature orderings/coalitions). If you later install `shap`
(`pip install shap`), you can swap `PhishGuardModel.explain()` for a
`shap.TreeExplainer(self.clf)` call with minimal changes — the rest of
the app doesn't need to know the difference, since it just expects a
list of `{feature, value, contribution}` dicts back.

## 6. Concept drift detector — how it works and how to tune it

`src/drift.py` implements DDM (Gama et al., 2004): it tracks the
running error rate and its standard deviation, remembers the best
(lowest) point seen so far, and flags `WARNING` / `DRIFT` when the
current error rate rises significantly above that best point.

Tunable in `DDMDriftDetector.__init__`:
- `min_samples` (default 100) — how many labeled predictions to see
  before the detector starts evaluating drift. Too low and you'll get
  false alarms from statistical noise; too high and real drift takes
  longer to catch.
- `warning_factor` / `drift_factor` (default 2.0 / 3.0) — standard
  DDM multipliers; raise them to make the detector less sensitive.

In `src/streaming_simulation.py`, `retrain_buffer` controls how many
of the most recent labeled examples are used to retrain when drift
fires (default 150) — bigger buffers give sturdier retrains but react
to drift more slowly.

## 7. Known limitations (be upfront about these)

- **Synthetic dataset**: patterns are rule-generated, not real-world.
  Real phishing campaigns are messier and more varied — retrain on
  real data before relying on this for anything.
- **HTML features are optional but matter a lot**: URL-only scans are
  meaningfully less accurate — the web UI and API tell you when a
  result was scored from the URL alone.
- **Explainability is ablation-based, not exact SHAP** — see Section 5.
- **DDM assumes labeled feedback exists in production** (e.g. a user
  reporting a missed phish, or a delayed ground-truth feed). In a real
  deployment you'd need a mechanism to get those labels back to the
  detector — this repo simulates that with the synthetic generator in
  `streaming_simulation.py`.
- **No browser-extension / live-fetch component**: the app expects the
  caller (you, or whatever wraps this API) to supply the URL and,
  optionally, HTML it already has — it deliberately never fetches
  pages itself, which is what keeps it API-independent and fast.

## 8. Troubleshooting

- **`RuntimeError: No trained model found`** when starting the app →
  run Step 4 (`python3 train.py ...`) first.
- **`ModuleNotFoundError`** → you're not in the virtual environment, or
  Step 2 wasn't run. Re-run `pip install -r requirements.txt`.
- **Port 5000 already in use** → edit the port number in `run_app.py`
  (`app.run(host="0.0.0.0", port=5000, ...)`) to something free, e.g. `5050`.
- **Warnings about "X does not have valid feature names"** → harmless
  sklearn warning if you're calling `model.clf.predict_proba` directly
  with a raw array instead of through `PhishGuardModel` methods; use
  the provided methods and this won't appear.
